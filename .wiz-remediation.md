## 1. Vulnerabilities (54 total)

### Root Causes

Most vulnerabilities stem from:

1. **Outdated Docker base images** (Python, Node.js)
2. **Vulnerable npm dependencies** (especially transitive dependencies)
3. **Vulnerable Python packages** (in requirements.txt)

### Remediation Steps

#### A. Update Docker Base Images

**Current vulnerable images:**

- `python:3.11-slim` → Update to `python:3.12-slim` or `python:3.13-slim`
- `python:3.12-slim` → Pin to latest patch version
- `node:20-slim` → Update to `node:20-alpine` or pin to latest LTS patch

**Action Plan:**

1. Update all Dockerfiles to use latest patched versions:

   ```dockerfile
   # Instead of:
   FROM python:3.11-slim

   # Use:
   FROM python:3.13-slim
   # or for better security:
   FROM python:3.13-alpine
   ```

2. For Node.js services:

   ```dockerfile
   # Instead of:
   FROM node:20-slim

   # Use (more secure, smaller):
   FROM node:20-alpine
   # or pin to specific patch:
   FROM node:20.11.1-alpine
   ```

**Files to update:**

- `apps/ai-platform/orchestrator-service/Dockerfile` (python:3.12-slim)
- `apps/ai-platform/knowledge-api/Dockerfile` (likely python)
- `apps/ai-platform/ingestion-pipeline-service/Dockerfile` (likely python)
- `apps/ai-platform/agentic/Dockerfile` (node:20-slim)
- `apps/ci-portal/Dockerfile` (node:20-slim)
- `apps/ci-portal/backend/Dockerfile` (python:3.11-slim)
- `apps/demo_app/Dockerfile` (python:3.11-slim)
- `apps/mcp_calculator/Dockerfile` (python:3.11-slim)

#### B. Update npm Dependencies

**High-risk npm packages** (common CVEs):

- `vite` - XSS vulnerabilities in older versions
- `express` - Multiple security issues
- Transitive dependencies in React/UI libraries

**Action Plan:**

```bash
cd apps/ai-platform
pnpm audit --audit-level=high
pnpm update --latest  # Updates to latest compatible versions
pnpm audit fix        # Automatically fix vulnerabilities

# For packages directory
cd packages/ui
pnpm audit fix

cd ../chat
pnpm audit fix
```

#### C. Update Python Dependencies

**High-risk Python packages:**

- `urllib3` - SSRF vulnerabilities
- `requests` - SSL verification issues
- `cryptography` - Various security issues
- `idna` - Known vulnerabilities in older versions

**Action Plan:**

```bash

pip install --upgrade <package-name>

# Update requirements.txt with specific versions

```

## 2. IaC Misconfigurations (1 High)

### Common Terraform Security Issues

Likely finding:

- **Publicly accessible Cloud Run services** (should use IAP)
- **Missing VPC egress settings**
- **Overly permissive IAM roles**
- **Missing binary authorization**
- **No Cloud Armor policies**

### Remediation Steps

#### Check Current Configuration

```bash
cd lab
terraform plan | grep -i "public\|ingress\|iam"

cd apps/ai-platform/agentic/k8s
grep -RniE "ingress|loadBalancer|serviceAccountName|secretRef" .
```

#### Ensure Services Use IAP (Already Configured)

Your services already have IAP configuration in `lab/terraform.tfvars`:

```hcl
# ✅ Good - using IAP
enable_iap = true
invoker_iam_disabled = true  # Blocks public access
```

#### Additional Hardening

Add to each service's Terraform:

**apps/ai-platform/\*/tf/main.tf:**

```hcl
resource "google_cloud_run_service" "service" {
  # ... existing config ...

  template {
    spec {
      # Add security context
      containers {
        # ... existing config ...

        resources {
          limits = {
            cpu    = "1000m"
            memory = "512Mi"
          }
        }

        # Run as non-root (already doing this via Dockerfile)
        # security_context {
        #   run_as_user = 1000
        #   run_as_non_root = true
        # }
      }

      # Enable binary authorization
      # binary_authorization {
      #   use_default = true
      # }
    }

    metadata {
      annotations = {
        # Restrict ingress to GLB only
        "run.googleapis.com/ingress" = "internal-and-cloud-load-balancing"

        # Enable VPC egress
        "run.googleapis.com/vpc-access-egress" = "private-ranges-only"
      }
    }
  }
}
```

## 3. SAST Findings (70 total: 50 Medium, 20 Low)

### Common Code Security Issues

Static Application Security Testing (SAST) findings typically include:

#### A. **Hardcoded Secrets/Credentials** (HIGH PRIORITY)

**Check for:**

```bash
# Search for potential secrets
git grep -i "password\|secret\|api_key\|token" --ignore-case | grep -v ".md\|SKILL\|README" | head -20
```

**Already Fixed:**

- ✅ OAuth credentials moved to Secret Manager
- ✅ No secrets in repository (Wiz scan shows 0 secrets)

#### B. **Insecure Cryptography**

Common issues:

- Using MD5/SHA1 instead of SHA256+
- Weak random number generation
- Insecure SSL/TLS settings

**Check for:**

```bash
grep -r "MD5\|SHA1\|md5\|sha1" apps/ --include="*.py" --include="*.ts" --include="*.js"
```

#### C. **SQL Injection / Command Injection**

**In Python services:**

- Avoid string concatenation in SQL queries
- Use parameterized queries with SQLAlchemy
- Sanitize user inputs

**In Node.js services:**

- Use prepared statements in drizzle ORM (already doing this ✅)
- Validate all user inputs with Zod schemas (already using ✅)

#### D. **Cross-Site Scripting (XSS)**

**Frontend Issues:**

- Avoid `dangerouslySetInnerHTML` in React
- Sanitize user-generated content
- Use Content Security Policy headers

**Check frontend code:**

```bash
grep -r "dangerouslySetInnerHTML\|innerHTML\|eval(" apps/ai-platform/agentic/client --include="*.tsx" --include="*.ts"
grep -r "dangerouslySetInnerHTML\|innerHTML\|eval(" apps/ci-portal/client --include="*.tsx" --include="*.ts"
```

#### E. **Path Traversal**

**Check for:**

```bash
# Look for file operations with user input
grep -r "readFile\|writeFile\|fs\." apps/ --include="*.ts" --include="*.js" --include="*.py" | grep -v "node_modules\|dist"
```

#### F. **Missing Input Validation**

**Already Using:**

- ✅ Zod schemas for TypeScript validation
- ✅ Pydantic models for Python validation

#### G. **Insecure Dependencies**

See section 1B and 1C above.

## 5. Automation Recommendations

### Add to CI/CD Pipeline

**Create `.github/workflows/security-scans.yaml`:**

```yaml
name: Security Scans

on:
  pull_request:
    branches: [main, develop]
  push:
    branches: [main]

jobs:
  npm-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
        with:
          version: 9
      - name: Install dependencies
        run: |
          cd apps/ai-platform
          pnpm install --frozen-lockfile
      - name: Run npm audit
        run: |
          cd apps/ai-platform
          pnpm audit --audit-level=high

  python-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install pip-audit
        run: pip install pip-audit
      - name: Scan orchestrator dependencies
        run: |
          cd apps/ai-platform/orchestrator-service
          pip-audit -r requirements.txt
```

### Dependabot Configuration

**Create `.github/dependabot.yml`:**

```yaml
version: 2
updates:
  # npm dependencies
  - package-ecosystem: "npm"
    directory: "/apps/ai-platform"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 10

  # Python dependencies
  - package-ecosystem: "pip"
    directory: "/apps/ai-platform/orchestrator-service"
    schedule:
      interval: "weekly"

  # Docker images
  - package-ecosystem: "docker"
    directory: "/apps/ai-platform/agentic"
    schedule:
      interval: "weekly"
```
