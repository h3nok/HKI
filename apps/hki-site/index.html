Hermetic
Knowledge Isolation

A signed runtime contract for enterprise agentic systems. Defines the isolation invariant that every RAG pipeline, tool call, cache write, and async job must preserve.

Every runtime request carries exactly one signed HKI envelope describing one active domain. Every artifact, cache key, tool call, retrieval, memory write, and gateway target is bound to that domain by exact equality. Cross-domain visibility exists only through explicit, audited publication. The runtime fails closed on missing, expired, global, wildcard, or mismatched domains.

Core Invariants

Every conforming implementation must enforce all six invariants. They are tested by @hki/conformance (28 cases, HKI-C01..C28).

  • 1
    One active domain per request. No global, no wildcard, no nullable. The active domain must appear in authorized_domains.
  • 2
    Signed envelope at every hop. The gateway mints and signs the envelope. Each downstream service validates it before processing.
  • 3
    Exact-equality reads only. No prefix matching, no glob expansion, no implicit inheritance. Use sameHkiDomain() / same_domain().
  • 4
    Domain-bound cache keys. org_id and active_domain are part of every cache, memo, and embedding key.
  • 5
    Body arguments cannot override the envelope. scope, domain, and stream_id fields that disagree with the signed envelope cause a hard 403.
  • 6
    Admin paths are physically separate. Runtime code cannot import from or call admin/governance modules. Cross-domain inspection is admin-plane only.

Envelope schema hki/1.0

hki-envelope.json 
{
  "hki_version":        "1.0",
  "envelope_id":        "env_01HX...",
  "org_id":             "acme",
  "subject_id":         "user:42",
  "active_domain":      "payments",     // MUST NOT be "global" or "*"
  "authorized_domains": ["payments", "hr"],
  "purpose":            "retrieve",
  "risk_tier":          "read-only",
  "policy_pack_id":     "payments@2026-04",
  "issued_at":          1714867200,
  "expires_at":         1714870800,
  "issuer":             "gateway@acme.example",
  "signature":          "ed25519:<base64>"
}

Install

Runtime packages for TypeScript and Python. The conformance kit runs against any implementation.

TypeScript runtime 
$ npm install @hki/runtime

// Validate an envelope
import { verifyEnvelope } from "@hki/runtime";
const result = verifyEnvelope(envelope);
Python runtime 
$ pip install hki-runtime[fastapi]

# FastAPI middleware
from hki_runtime.fastapi import HkiMiddleware
app.add_middleware(HkiMiddleware)
Conformance kit 
$ npm install @hki/conformance

# Run 28 conformance cases
$ pnpm verify:hki-conformance
$ pnpm probe:smoke   # HTTP probes
SDK (mint + wrap) 
$ npm install @hki/sdk

import { mintEnvelope } from "@hki/sdk/client";
const env = mintEnvelope({
  activeDomain: "payments", ...
});

Conformance Levels

A conformance level is a claim backed by reproducible evidence, not a self-assessment. Run pnpm registry:build to generate a signed conformance.json for your implementation.

L0
Documented

Domain-sensitive surfaces inventoried. No runtime claim made.

L1
Labeled

Runtime artifacts carry non-null org and domain labels.

L2
Routed

Requests carry one signed active-domain envelope through each hop.

L3
Enforced

Runtime rejects missing, global, wildcard, or cross-domain scope.

L4
Tested

Automated negative tests and HTTP probes prove isolation invariants.

L5
Audited

Signed release evidence independently reviewed with external reference.
